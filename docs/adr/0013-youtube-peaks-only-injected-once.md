# YouTube 시청자 데이터는 많이 본 구간만 쓰고, 서버가 요청마다 한 번만 붙인다

[ADR 0010](0010-youtube-oauth-retention-and-direct-upload.md)은 시청자 유지율 곡선에서 많이 본 구간과 적게 본·이탈 구간을 함께 뽑아 Gemini에게 "넣어라"와 "빼라"를 같이 지시했다. 시작 화면의 `데이터로 프롬프트 튜닝` 버튼과 채널 Shorts 성과 자동 추가는 같은 데이터를 Editorial Prompt 글에도 적었다.

샘플 데이터로 실제 분석을 돌려 보니 세 가지가 드러났다.

- 이탈 구간은 3구간 전보다 얼마나 떨어졌는지로 골랐다. 그래서 반복 시청 피크가 끝나고 평소 수준으로 돌아오는 구간이 "급격한 이탈"로 잡혔고, 같은 프롬프트에 "45-61초 우선"과 "53-69초 제외"가 함께 들어갔다. Gemini는 제외 지시를 거의 따르지 않았다.
- 유지율은 시청자가 빠져나가며 줄기만 하므로 영상 앞부분이 늘 높다. 피크 점수에 유지율 값을 그대로 넣자 상대 성과가 평균(50%)인 인트로가 "반복·집중 시청 구간"이 됐고, Gemini는 이를 근거로 클립을 골랐다.
- 튜닝 버튼을 누르면 서버의 `format_retention` 섹션과 같은 피크·댓글·Shorts 성과가 프롬프트에 두 번 들어갔다.

그래서 다음처럼 정한다.

- 적게 본·이탈 구간은 추출, 모델(`retentionLows`), 프롬프트, 화면(배지, 그래프 띠, 목록)에서 모두 없앤다. 예전 `youtube.json`의 `retentionLows`는 읽을 때 무시된다.
- 많이 본 구간은 YouTube의 상대 유지 성과(`relativeRetentionPerformance`)와 이웃 구간보다 솟은 정도(반복 시청)로만 점수를 매긴다. 유지율 값 자체는 점수에서 뺀다. 영상 앞 30%는 점수를 0.3배에서 1배로 서서히 올려 낮게 친다. 상대 성과가 0.55 미만이고 솟지도 않은 구간은 피크로 치지 않으므로 피크가 4개보다 적을 수 있다.
- YouTube 데이터는 서버가 Analysis(`prompts/analysis.py` `format_retention`)와 Edit Request(`prompts/edit_agent.py`)에 중복 없이 한 번만 반영한다. 사용자가 시작 화면에서 `✨ 데이터로 프롬프트 튜닝`을 누르면 프롬프트에 `[YouTube 데이터 기반 맞춤 지시]`(피크 구간, 챕터, 댓글)가 들어가고 `데이터 튜닝 적용됨` 배지가 표시된다. 이때 서버는 프롬프트에 이미 맞춤 지시가 들어있는 것을 감지하여 `# Source Video` 섹션에서 피크·챕터·댓글의 중복 첨부를 건너뛴다. 튜닝 버튼을 누르지 않은 기본 프롬프트 상태에서는 종전처럼 서버가 `# Source Video` 아래에 시청자 데이터를 자동으로 첨부하여 전달한다. 따라서 어떤 경우든 동일 데이터는 Gemini에게 단 1회만 전달된다.

## Considered Options

- 이탈 구간 판정을 고쳐서 남기는 안: 피크 뒤 하강과 진짜 이탈을 가르려면 기준이 더 늘어나고, 고쳐도 Gemini가 제외 지시를 약하게만 따랐다. 사용자가 필요 없다고 정했다.
- 앞부분 가중치만 낮추고 유지율 값 점수는 두는 안: 유지율은 영상 끝까지 줄어서, 가중치 경계 바로 뒤가 새로운 "앞부분"이 될 뿐이었다(샘플에서 0:22, 0:27, 0:34로 밀려나기만 했다).
- 버튼을 완전히 없애고 서버 자동 첨부만 남기는 안: 중복은 사라지지만, 크리에이터가 시청자 데이터를 직접 눈으로 확인하고 지시를 추가·수정할 수 있는 실습 인터랙션이 사라져 채택하지 않았다. 프런트엔드 튜닝 버튼을 유지하되 백엔드에서 중복을 걸러내는 방식으로 정했다.
