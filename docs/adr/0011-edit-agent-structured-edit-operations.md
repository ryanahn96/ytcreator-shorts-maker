# 말로 편집은 구조화 출력 한 번으로 편집 동작 목록을 받아 브라우저가 한 단계로 적용한다

편집 화면에 Edit Agent를 넣는다. 화면 이름은 '말로 편집'이다. 사용자가 음성이나 글로 건넨 Edit Request를 알아듣고, 지금 보고 있는 Shorts의 편집 값을 바로 바꾼다. 다른 Shorts는 바꾸지 않고, 여러 Shorts를 한꺼번에 바꾸는 요청도 받지 않는다. 바꿀 수 있는 값은 사람이 화면에서 바꿀 수 있는 값과 같다: Clip 구간과 순서, Look, 자막 글자, 단어 지우기. Analysis를 다시 하거나 Render, 업로드를 하지는 않는다. 편집 상태는 지금도 브라우저 reducer인 `frontend/src/lib/editor.ts`에만 있고 서버는 들고 있지 않다.

그래서 다음과 같이 정한다.

- Edit Request 하나에 Gemini 호출 한 번이다. `response_json_schema` 구조화 출력과 `ThinkingLevel.LOW`로 편집 동작 목록과 한 줄 답장을 함께 받는다. 모델은 Analysis와 같은 Flash 체인을 쓰고, 말로 편집 비용은 화면에 보이지 않는다.
- 브라우저가 요청마다 지금 Shorts의 상태, 고른 Clip과 재생 위치, 이번 대화 기록을 보낸다. 서버는 보관해 둔 전체 자막 `transcript.json`에 단어 번호를 붙여 프롬프트에 넣는다. 서버는 편집 상태도 대화 기록도 저장하지 않는다. 대화 기록은 브라우저 메모리에만 있어 새로고침이나 새 Analysis 때 사라진다.
- 편집 동작은 Clip을 화면의 Clip Number로 가리킨다. 사용자가 클립 ID보다 직관적이라며 골랐다. 번호는 요청을 보낸 순간의 번호다. 브라우저는 보낼 때 번호와 `clipId`를 짝지어 두고, 답이 오면 모든 번호를 그 짝으로 한 번에 바꾼 뒤 적용한다. 그래서 한 요청 안의 동작끼리 번호를 밀어내지 않고, 기다리는 사이 손으로 클립을 옮겨도 다른 클립이 바뀌지 않는다. 그사이 지워진 클립을 가리키는 동작은 건너뛴다.
- 서버는 동작 값을 Render 계획과 같은 pydantic 범위(영상 박스 최소 크기 120 포함)로 검사한다. 범위 밖 값은 가장 가까운 허용값으로 맞추고, 기존 박스와 합쳐진 영상 박스가 캔버스 안에 들어오도록 맞추는 일은 브라우저가 각 Look별로 마저 처리하며, 모르는 동작은 버린다. 그래서 말로 편집이 만든 값 때문에 `/render`가 422를 내지 않는다.
- 브라우저는 받은 동작 목록 전체를 실행 취소 한 단계로 바로 적용하고, 오른쪽 아래 플로팅 위젯에서 답장 전문과 조정·건너뜀 안내 전체, 되돌리기 버튼을 말줄임 없이 보여 준다. 이를 위해 편집 화면에 손 편집과 말로 편집을 함께 다루는 실행 취소와 다시 실행이 생긴다.

## Considered Options

- Gemini function calling으로 동작을 하나씩 부르는 안: 요청 하나에 여러 번 왕복한다. 편집 상태가 브라우저에만 있어 서버가 중간 상태를 흉내 내야 한다.
- 바뀐 Scenario JSON 전체를 돌려받아 통째로 갈아 끼우는 안: 출력이 길어 느리고, 사용자가 말하지 않은 값까지 바뀔 수 있다.
- Gemini Live 음성 모델 `gemini-3.8-live`에 도구를 붙여 말로 편집 전체를 맡기는 안: 글 입력과 말 입력이 다른 길을 타고, 쓰지 않을 음성 답변과 세션 관리가 따라온다.
